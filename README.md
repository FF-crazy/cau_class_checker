## 它是怎么工作的

教室屏幕上那张二维码里，真正有用的只有两个参数：

| 参数 | 含义 |
|---|---|
| `ip` | 教室网络的出口 IP |
| `ipt` | 这一场签到的**开始时刻**，形如 `260922174709` = 2026-09-22 17:47:09 |

剩下两个 `t` / `tt` 是配 `ip` 的**时间签名**，很快就作废 —— 这正是转发的截图常常签不上的原因。

这个 App 做的就一件事：**把旧的 `t`/`tt` 丢掉，用当前时间重算一遍。**

```
从摄像头 / 相册 / 粘贴板拿到 ip、ipt  →  按当前时间重算 t、tt  →  当场可用的码 / 直接签到
```

签到请求必须**从教室网络里发出去**，所以云端代签在原理上就不成立，还是得有一台实体机器待在教室里。

## 用法

### 一、先添加账号

「账号管理」→ 填学号和统一身份认证密码 → 登录。

* 一个账号存一份**独立**的会话 Cookie，所以多个账号能同时在线，一次全签。
* 密码只用来换 Cookie，**不落盘**；Cookie 用 Android Keystore 加密后存在本机。
* 有效期大约一个月，**没有自动续签**。到期后重新登录一次即可。

### 二、拿到签到码

首页有三条路，随便哪条：

| 入口 | 用法 |
|---|---|
| 从摄像头导入 | 对着教室屏幕上的码扫 |
| 从相册导入 | 截图存下来，再从相册选 |
| 粘贴板 / 手动粘贴 | 把 `https://class.cau.edu.cn/casgeosig.php?ip=…&ipt=…&t=…&tt=…` 整条粘进来，点「生成」 |

**旧码照样能用。** 老师转发的、同学截图的、你十分钟前拍的都行 —— `t`/`tt` 会被丢掉重算，真正携带身份的只有 `ip` 和 `ipt`。

三条路都汇到同一个地方：一张跟着当前时间刷新的二维码，可以直接举着让同学扫。

### 三、签到

进入会话页后：

| 按钮 | 作用 |
|---|---|
| **全部签到（N 个账号）** | 所有账号依次签一遍。绿色的是主操作 |
| 手动签到（逐个点） | 托底方案，见下文 |
| 打开签到链接 | 用系统浏览器打开看一眼 |
| 立即刷新 / 复制链接 | 手动重算一次 / 复制当前链接 |
| 分享链接 | 把当前链接发出去 |

「每 0.5 秒自动刷新」开关控制二维码是否随时间自动重算，默认开着。

两个容易误会的地方：

* **「打开签到链接」不会带你在 App 里登录的会话。** 浏览器有它自己的 Cookie，所以打开后多半会跳去统一身份认证。它主要是用来看的。
* **「分享链接」分享的就是那条签到链接本身**，带着当前时间的 `t`/`tt`。对方点开走的是学校的签到流程，需要他自己已登录。**链接里的签名很快就过期**，转发慢了就没用了 —— 真想帮同学，把手机上这张会自己刷新的二维码递过去更实在。

### 四、严格模式

如果扫到的链接是 `casgeopicsig.php` 而不是 `casgeosig.php`，这一场就是**严格模式**：签到除了位置，还要交一张**现场照片**。

App 会自己认出这种链接，点「全部签到」后弹出「打开相机 / 从相册选」。照片会被压到长边 1280、质量 80，再转成 base64 提交。

**照片所有账号共用一张** —— 同一台手机、同一个时刻、同一间教室，本来也只有一张可拍。

## 权限

| 权限 | 用来做什么 | 不给会怎样 |
|---|---|---|
| 定位 | 签到要带真实坐标 | 签到**照样成功**，只是教师端后台那一列是空的。App 会告诉你为什么没拿到 |
| 相机 | 扫码；严格模式拍照 | 扫码和严格模式用不了，相册导入仍然可用 |
| 网络 | 登录与签到 | —— |

定位取的是手机的**真实坐标**，没有写死任何教室位置；严格模式要的照片也只能现场拍。这两样是「人确实在场」的凭据。

## 手动签到（逐个点）：托底

无头 HTTP 是一条路，系统 WebView 是另一条。学校那边改了接口、或者要过人机验证时，后者还能用。

它用每个账号自己的 Cookie 逐个打开签到页：

* 落在统一身份认证页 → 判定会话失效，**跳过**；
* 读到「签到成功」「已签到」→ **自动关掉，开下一个**；
* 其余情况（码不对、LastVisit 超时）**停在这一页**，页面上有「重新加载」可以重试 —— 这两种是能重来的，自动跳过等于替你放弃一次可能成功的签到，而你未必注意到发生过什么。

## 构建

```bash
./gradlew testDebugUnitTest    # 单元测试
./gradlew assembleDebug        # 出 APK
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。

* Kotlin + Jetpack Compose（Material 3），`minSdk 29` / `targetSdk 37`
* 没有后端、没有 Gradle 之外的构建步骤、**不打包浏览器内核**（用系统 WebView），零 Google Play 服务依赖
* 开发机上没有模拟器，相机 / 定位 / 真机签到**只能真机验证**；JVM 单元测试是唯一的自动化防线
